# ADR-0005 — Паттерн "Провайдер моделей" (BYOK) для Этапа 4

**Статус:** принято.

**Контекст.** На Этапе 4 (AI Classification) требуется внедрение LLM для кластеризации и RAG-поиска. Изначально планировалась жесткая привязка к Ollama (локально) и Token Router (kimi-k3-free). Локальные LLM на Mac M1 (8GB) имеют ограничения по контексту и производительности, а бесплатные облачные API могут изменить условия предоставления услуг.

**Решение.** Внедрить паттерн "Провайдер моделей" (LLM Provider Interface) и подход Bring Your Own Key (BYOK). Бэкенд должен реализовывать абстрактный класс для работы с LLM, который поддерживает:
1. Ollama (Local)
2. OpenAI API
3. Anthropic API
4. Custom OpenAI-compatible URL (TokenRouter, Groq, DeepSeek).
Пользователь сам вводит свои API-ключи в настройках приложения.

**Обоснование.** Перенос вычислений на сторонние API по выбору пользователя снимает нагрузку с устройства, радикально повышает качество аналитики (за счет доступа к флагманским моделям вроде Claude 3.5 Sonnet) и защищает архитектуру от vendor lock-in.

**Последствия.** API-ключи пользователя становятся критическими секретами и должны храниться так же безопасно, как и сессия Telegram (в macOS Keychain). В API-контракт потребуется добавить эндпоинты для управления ключами.
