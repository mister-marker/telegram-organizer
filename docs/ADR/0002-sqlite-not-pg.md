# ADR-0002 — SQLite вместо Postgres/Supabase на этапах 1–5

**Статус:** принято.

**Контекст.** Продукт — local-first desktop-утилита для одного пользователя на одной машине (macOS M1/8GB), без серверного режима в MVP (`docs/PRD.md`, «Модель распространения»; `docs/ADR/0001-local-first.md`). Бюджет ресурсов жёсткий: приложение ≤ 2 ГБ RAM (NFR «Ресурсы»).

**Решение.** Использовать SQLite (файловое хранилище) как единственную БД на этапах 1–5. Supabase/PostgreSQL вводится только на Этапе 6, когда впервые появляется реальная межустройственная задача — синхронизация метаданных и плана между устройствами (`docs/ADR/0004-supabase-later.md`).

**Обоснование.** Клиент-серверная БД добавляет отдельный процесс, сетевой порт и конфигурацию ради возможностей (конкурентный доступ многих клиентов), которые local-first single-user приложению на этапах 1–5 не нужны. SQLite не требует отдельного процесса, укладывается в бюджет RAM и не создаёт лишнего сетевого интерфейса, который потребовалось бы дополнительно защищать, — что прямо поддерживает требование «данные не покидают Mac пользователя».

**Последствия.** Переход на Supabase/PostgreSQL на Этапе 6 потребует отдельного слоя инкрементальной синхронизации (FR-20) — это заложено заранее и не считается техдолгом.

**Связано с:** FR-20, `docs/ARCHITECTURE.md` §1 (таблица «Эволюция продукта», этап 6), `docs/PRD.md` §7 «Интеграции» (Supabase/PostgreSQL, Этап 6+).
