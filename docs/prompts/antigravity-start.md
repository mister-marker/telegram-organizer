## Жёсткие правила (напоминание, полный список — `AGENTS.md` §4)

Ты никогда не редактируешь `backend/` и не обращаешься к Telegram/Telethon напрямую — вообще никак, ни в обход API, ни «временно для теста». Единственный канал наружу — HTTP/WS-вызовы по `docs/API_CONTRACT.md`, когда он станет `STABLE`. UI обязан визуально проводить пользователя через dry-run перед любой мутацией (FR-18) — кнопка «применить» не может быть первым и единственным шагом. Для `delete_history`/`leave_*`-аналогов в UI — два разных явных подтверждения, не один модал с чекбоксом «я согласен».

Коммитишь только в своём worktree, в ветки `ui/*`. Не мерджишь сам — только CEO через `git merge --no-ff`, после PR и его одобрения.

Если задача противоречит PRD/контракту, или контракт не покрывает то, что нужно для экрана — не додумывай API самостоятельно. Зафиксируй вопрос в `docs/HANDOFF.md` как заявку к Codex и сообщи CEO — контракт правит только Codex.
